## 2. P1 — 近期（1–2 周）

### 2.1 稳定性观察项（v1.3.0 发布后守两个星期）

上版动了七类高危路径（Cookie 加密迁移、成绩身份、通知消费顺序、混合内容、picks 对账、CAS 并发、空 catch）。观察渠道：CrashGuard 本地日志（用户反馈时附带）+ QQ 频道反馈。**出现频率最高的前两名优先修。**

### 2.2 一卡通「直读型费项」支持（实测发现的真实缺口）

复现电费问题时从官方前端 `app.cb5250f3.js` 提取到的契约：`feeitem.flag[4]==4` 的费项**不需要级联**，直接 `type=IEC, level=0` 就能出数。我们目前对这类费项仍要求选满——若学校配了直读型费项（如全局水费），应用会卡在「请先选择」。工作量 ~0.5 天（`YktFeeItemDetail` 加 flag 解析 + YktScreen 分流）。

### 2.3 network 更新链路测试（JaCoCo 指出的最大零覆盖块）

`AppDownloader`(114 行) / `UpdateCenter`(32) / `UpdateNotifier`(45) = 191 行零覆盖。需要 Robolectric + 本地 HTTP fixture。更新是所有用户都会走的路径，值得补。~1 天。

## 3. P2 — 功能迭代（1 个月窗口）

按用户价值排序，**做之前先在 QQ 频道确认需求量**：

1. **电费余额多房间**：家里有多个电表/多间宿舍的用户（辅导员、合租）希望保存多个房间轮询。`YktSelectionStore` 从"单选记忆"扩成"多房间收藏夹"。~2 天。
2. **成绩趋势图**：绩点/均分按学期折线。数据都在本地（`GradesCacheManager`），纯 UI + 一个纯函数计算层。~1.5 天。
3. **课表 widget 完善**：桌面卡片已有，补「今天剩余课程」样式与点击直达当前课。~1 天。
4. **题库统计页增强**：按章节正确率热力图，指出薄弱章节。`ReviewDatabase` 已有数据。~1 天。
