## 2. 新功能模块提案（按校园生活领域划分）

> 上一版只围绕题库，面太窄 —— 这一版按**领域**铺开：课表 / 考试 / 一卡通 / 二课 / 学工 / 生活工具 / 数据回顾。
> 每个都是应用现在**完全没有**的能力，且都有独立入口、数据与界面（模块级，不是给旧页面加图表）。
>
> 三个技术前提：
> - **纯离线**：没有服务器 → 涉及"同学之间"的只能做**文件交换**，不能在线匹配。
> - **新依赖要能离线拿到**：ML Kit（OCR）不在本机 Gradle 缓存，**拍照录题暂时做不了**；TTS 是系统 API，可行。
> - **新表要迁移**：落新数据的模块都要 `DB_VERSION` +1 并写迁移。

## 2.1 课表与校园时间

### C1. 校历（学期时间轴：上课周、放假、调休）　~4 天　★★★★★

**是什么**：一张真正的学期日历 —— 第几教学周、哪天放假、哪天调休补课、期末考试周是哪几周。

**为什么需要**：现在应用**只知道"第一周周一是哪天"**，不知道放假与调休。于是国庆、清明这类假期里，课表照样显示有课，提醒也照响；调休补课的日子又完全不显示。

**做法**：
- 学期起止与节假日由用户**一次性录入**（或从学校公告里手动补几条），存本地
- 课表渲染与提醒统一过滤掉放假日；调休日按"补哪天的课"覆盖显示
- 这是所有时间类功能的地基（M 系列日程、考试周模式都要它）

**风险**：节假日每年不同、学校调休安排也各不相同 → 必须允许随时编辑，且**默认不猜**（没录入就按现有行为走）。

### C2. 调停课速报　~3 天　★★★★☆

**是什么**：从教务消息里识别「停课 / 调课 / 补课 / 更换教室」这类通知，单独汇总成一条时间线，并联动课表标示"这节课已调整"。

**为什么需要**：调停课通知混在几十条教务消息里，学生最常漏。而漏一节课的代价比漏一条通知大得多。

**数据**：`AcademicMessage`（标题 + 正文，`MessageCenterManager` 已缓存）。用规则匹配关键词 + 日期，匹配不到的原文照旧展示。

**风险**：规则匹配必然有误判 → 每条都要能点开原文，绝不自动改课表（只做提示与标记）。

### C3. 同伴课表比对（无服务器）　~3 天　★★★☆☆

**是什么**：导入同学分享的精简课表文件，叠加显示，自动算出**双方都空闲**的时间段，用来约自习/组队。

**做法**：导出侧产出只含时间格的 JSON（**不含学号姓名**）；导入侧做时间格差集。全程不联网。

## 2.2 考试与学业

### C4. 考试周模式　~3 天　★★★★☆

**是什么**：进入考试周后，首页切换成专用视图：距离下一场考试的倒计时、每科座位与考场、该科复习进度（关联题库/闪卡）、自动静音与免打扰。

**为什么需要**：考试周的关注点和平时完全不同，现在要自己在几个页面之间来回找。

**数据**：`AcademicExam`（含 `seat` 座位号、`time`、`location`）。

### C5. 补考重修追踪　~3 天　★★★★☆

**是什么**：成绩里出现不及格时自动建档，追踪这门课的补考安排、重修选课时间与最终成绩，直到销案。

**为什么需要**：挂科后补考时间往往只在通知里出现一次，错过就是一整年。

**数据**：`AcademicGradeReport`（分数）+ 考试列表 + 消息。判定规则（多少分算挂）**要让用户确认**，不同课程口径可能不同。

### C6. 学业体检报告　~4 天　★★★★☆

**是什么**：风险评估报告：挂科清单、学分进度、GPA 趋势、二课积分缺口，标出"高危项"并给建议。每学期生成一份可存档。

**边界**：学校接口**没有培养方案数据** → 毕业学分要求必须**用户自填**，应用只算差值，绝不编造学校规定。

## 2.3 一卡通与生活

### C7. 宿舍电费分摊账本　~3 天　★★★★☆

**是什么**：一间宿舍、几个人、每人该出多少。把应用已经能查到的电费余额/充值记录与"谁交了钱"记在一起，自动算出谁欠谁多少。

**为什么需要**：宿舍电费 AA 是真实的高频摩擦点，现在靠群里接龙记。

**数据**：`YktBillRecord`（充值/消费流水）+ 用户自建的"室友名单"。完全本地。

### C8. 消费分析　~3 天　★★★☆☆

按月汇总、按商户/地点分类、食堂 vs 超市占比、超支提醒。数据在 `YktBillRecord`（商户、地点、收支类型都有）。

## 2.4 学工与办事

### C9. 请假条生成　~3 天　★★★★☆

**是什么**：把填写好的请假单导出成**规整的图片/PDF**（含姓名、学号、事由、起止时间、监护人电话），用于线下交给辅导员或打印。

**为什么需要**：线上提交之外，很多场景仍要一张纸。现在只能自己截图，格式乱、信息缺。

**前置**：`XuegongLeaveDraft` 已经有全部字段，导出只是排版渲染。

### C10. 办事清单（材料与流程指引）　~3 天　★★★☆☆

**是什么**：常见办事事项（补办学生证、开在读证明、缓考申请…）的材料清单与流程，做成可勾选的清单，能自己增删条目。

**边界**：**不编造学校流程** —— 内置条目只写通用常识，具体材料由用户自己填或从公告里摘。

## 2.5 资料与工具

### C11. 课程资料库　~4 天　★★★★★

每门课一个资料夹，课件/讲义/往年卷按课程归档，应用内直接看（PDF/图片/xlsx/docx 渲染已支持）。文件留在系统原位置（只存 URI），不复制进私有目录。

**风险**：URI 会失效（用户删文件/换手机）→ 打开失败要能提示并允许重新关联。

### C12. PDF 工具箱　~4 天　★★★☆☆

合并、拆分、提取页面、图片转 PDF。现有 `PdfRenderer` 已能渲染 PDF，但没有编辑能力。

**风险**：写 PDF 需要新依赖（`pdfbox-android` 之类）→ **先确认能否离线获取**，拿不到就作废这一项。

### C13. 证件照与材料扫描　~3 天　★★★☆☆

按常见规格（一寸/二寸/学籍照）裁剪并导出，带白底替换。`ImageCropActivity` 已有裁剪基座。

## 2.6 数据回顾与通知

### C14. 周报与学期回顾　~3 天　★★★★☆

每周自动生成回顾：上了几节课、刷了多少题、一卡通花了多少、收到几条通知；学期末出总回顾长图。**只做回顾，不做打卡与连续天数**（你已否决）。

### C15. 通知历史中心　~2 天　★★★☆☆

把六类提醒（课程/考试/成绩/消息/电费/复习）实际发出的记录留档，可回看"上周都提醒了什么"。现在通知发完就没了，用户常问"刚才那条是什么"。

### C16. 校园服务入口聚合　~2 天　★★☆☆☆

教务、一卡通、图书馆、网络中心、宿舍报修等常用系统的快捷入口与说明，一处跳转。

## 2.7 题库域（只占一小块，不再铺开）

### C17. 闪卡记忆（间隔重复背诵）　~5 天　★★★★☆

正面问题、翻面答案，按遗忘曲线排期。卡片来源：手输、从题库一键生成、从课程笔记生成。排期复用现有 `ReviewScheduling`。

### C18. 番茄钟专注　~3 天　★★★☆☆

25 分钟专注 + 5 分钟休息，结束时记录这段时间做了多少题。可与题库/闪卡联动。

### C19. 听题模式（TTS）　~2 天　★★★☆☆

朗读题干与选项，通勤时听题。系统 TTS，零依赖；设备缺中文语音包时要能给安装提示。

### 做不了 / 不建议

| 想法 | 结论 |
|---|---|
| 拍照录题（纸质错题 OCR） | **暂时做不了**：ML Kit 不在本机离线缓存，构建装不上 |
| 在线约自习 / 找搭子 / 二手交易 | 需要服务器与内容审核，个人项目不该碰 |
| 学习打卡与连续天数 | 你已否决；C14 只做回顾 |
| 选课 / 抢课 | 协议层已删，真要做须按当时页面重写 |
| 全校课表查询 / 全校排名 | 学校未开放这些接口，拿不到数据就不能做 |
## 3. 明确不做（已有决策，避免反复讨论）

| 项 | 理由 |
|---|---|
| 学习打卡 / 连续天数 | 用户 2026-10-18 明确否决 |
| 选课 / 抢课 | 协议层已于 2026-10-19 删除（从未接界面、零覆盖）；真要做须按当时页面重写 |
| AI Key 静默续期 | 合规口径：凭据类操作必须用户显式触发 |
| 差量更新 | 包体已 9.8 MB，收益不成立 |
| 上架应用商店 | 需要企业资质与隐私合规材料，个人维护不划算 |
| 多语言 | 单校单一语种场景，无收益 |
